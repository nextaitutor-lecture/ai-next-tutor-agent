# #27. AI Agent란 무엇인가?
## 인트로·STEP 1 촬영용 개선 대본
기준일: 2026-10-04 · 목표: 작은 v0.1에서 LLM의 다음 행동 선택을 확인한다.
범위: 인트로와 STEP 1. 캘린더 실제 실행은 STEP 2에서 이어간다.

## 인트로

**강사**

AI가 나 대신 일정을 잡고, 티켓을 예매하고, 쇼핑까지 해준다.
이런 AI 에이전트 소개, 한 번쯤 들어보셨죠?

그런데 이런 AI 에이전트, 우리도 직접 만들 수 있습니다.

**학생**

제가요? 어디서부터 만들어야 할지 감도 안 잡히는데요.

**강사**

그렇죠. 저 말만 들으면 뭔가 엄청난 걸 만들어야 할 것 같잖아요.

그래서 이번 시간부터는 아주 작게 시작해서,
하나씩 기능을 붙여보려고 합니다.

우리가 만들 건 **나만의 출장 비서**예요.

자, 이렇게 일을 시켜보겠습니다.

**“다음 주 부산 출장 준비해줘.”**

이 말을 들은 우리 비서,
**가장 먼저 뭘 해야 할까요?**

[화면]
강사 중심. 요청 문구만 크게 표시한다.
일정·티켓·쇼핑 일러스트는 별도로 늘리지 않는다.

## STEP 1. 출장 준비를 맡기면 무엇부터 할까?

### 장면 1. 선택 결과를 짧게 먼저 보여주기

**강사**

교통편부터 찾을까요? 아니면 숙소부터?

우선 실행 결과를 잠깐 보겠습니다.

[화면 — 실제 LLM 호출에서 확보한 선택 결과]
```text
Selected Action | 선택한 행동
check_calendar    캘린더 확인
```

**강사**

캘린더를 먼저 확인하겠다고 하네요.
왜 이걸 골랐는지, 직접 만들어보면서 확인하겠습니다.

[촬영]
결과는 3~5초만 보여준다. 선택 이유는 장면 6에서 함께 확인한다.
촬영 전 실제 LLM 호출 결과를 확보한다. 이 화면은 그 실행 결과의 선공개다.

### 장면 2. 목표와 현재 상태 작성

**강사**

필요한 개발환경과 예제 코드는 영상 설명란에 정리해두겠습니다.

자, 먼저 우리가 맡길 일을 적겠습니다.
‘다음 주 부산 출장 준비’죠.

[화면 — 편집기에 입력]
```python
goal = "다음 주 부산 출장 준비"
```

**강사**

그런데 다음 주라고만 했지, 정확히 며칠인지는 아직 모르잖아요.
현재 알고 있는 정보에는 출장 날짜를 비워두겠습니다.

[화면 — 아래에 이어서 입력]
```python
current_state = {
    "trip_date": None  # 출장 날짜: 아직 모름
}
```

**강사**

여기서 None은 날짜가 아직 없다는 뜻이에요.

[촬영]
환경 설치 설명은 진행하지 않는다. 안내 자막만 잠깐 표시한다.
입력할 때 목표와 날짜 부분만 차례로 강조한다.

### 장면 3. 사용할 수 있는 기능 알려주기

**강사**

이제 AI에게 사용할 수 있는 기능을 알려줍니다.
캘린더 확인, 교통편 검색, 숙소 검색.
오늘은 이 세 가지 중에서 다음에 할 일을 골라보게 하겠습니다.

[화면 — 기능 목록 입력]
```python
available_actions = [
    "check_calendar",    # 캘린더 확인
    "search_transport",  # 교통편 검색
    "search_hotel"       # 숙소 검색
]
```

**강사**

지금은 기능의 이름을 알려주는 단계예요.
이름을 적었다고 캘린더가 바로 열리는 건 아니고요.

[촬영]
세 이름과 한글 주석을 함께 보여준다.
이 장면에서 각 함수 내부나 외부 서비스 연결을 설명하지 않는다.

### 장면 4. 작성한 내용을 Context로 연결

**강사**

지금 적은 걸 한글로 보면 이렇습니다.

[화면 — 코드 옆에 간단한 요약]
```text
목표              다음 주 부산 출장 준비
현재 알고 있는 정보  정확한 출장 날짜는 아직 모름
선택할 수 있는 행동  캘린더 확인 / 교통편 검색 / 숙소 검색
```

**강사**

앞에서 배운 Context죠.
LLM이 판단할 때 참고하도록,
목표와 현재 알고 있는 정보, 사용할 수 있는 기능을 함께 전달하는 겁니다.

[촬영]
새 도식으로 화면을 전환하지 않는다. 기존 코드 옆에 요약만 표시한다.
‘상황판’이라고 표현하더라도 사람이 작성해 전달한 정보임을 유지한다.

### 장면 5. LLM에게 다음 행동 선택 요청

**강사**

이제 LLM에게 이렇게 요청하겠습니다.

**“현재 상황에서 다음에 할 일을 하나 골라주고, 그 이유도 알려줘.”**

‘캘린더부터 확인해’라고 순서를 정해주지는 않겠습니다.
어떤 행동을 먼저 고를지 보죠.

[화면 — 실제 LLM 호출을 감싼 함수 사용]
```python
decision = ask_llm(
    goal,
    current_state,
    available_actions
)

print("Selected Action:", decision["action"])
print("Reason:", decision["reason"])
```

[촬영]
ask_llm은 실제 모델 호출이 구현된 함수여야 한다.
‘실제 LLM 호출’이라고 한 줄 표시한다.
함수 내부의 API 설정·인증·응답 파싱 설명은 이 장면에서 생략한다.
영상의 읽기 편의를 위한 표현 코드이며 현재 GitHub 예제와 동일한 실행 파일은 아니다.

### 장면 6. 결과에서 판단 확인

[화면 — 터미널 실제 실행 결과]
```text
Selected Action | 선택한 행동
check_calendar    캘린더 확인

Reason | 선택 이유
교통편과 숙소를 확인하려면
먼저 정확한 출장 날짜가 필요함
```

**강사**

캘린더 확인을 골랐네요.
이유도 보겠습니다.
교통편과 숙소를 찾으려면 정확한 날짜가 먼저 필요하다는 거죠.

우리가 작성한 건 목표, 현재 정보, 사용할 기능 목록이었죠.
그걸 보고 **지금 무엇을 먼저 할지는 LLM이 선택한 겁니다.**

[촬영]
실제 출력된 action과 reason을 사용한다.
이유의 문장이 달라지면 화면·대사를 그 결과에 맞춘다.
다른 행동이 나오면 그대로 확인하고, 입력 정보와 선택 이유를 검토한다.
정답처럼 보이도록 고정 문자열을 출력하지 않는다.

### 장면 7. 선택했는데 실제로 일했을까?

**학생**

그런데… 지금 캘린더를 확인한 거예요?
아니면 확인하겠다고 고르기만 한 거예요?

**강사**

좋아요. 그럼 출장 날짜가 들어왔는지 볼까요?

[화면 — 실행 후 현재 상태 확인]
```python
print(current_state)
```

```text
{'trip_date': None}
```

**강사**

아직 비어 있죠.
지금은 다음에 할 일을 고른 데까지입니다.
캘린더에서 실제 날짜를 가져오지는 않았어요.

‘확인하겠다’는 말은 나왔는데, 아직 확인은 안 한 거죠.

## 촬영 전 확인 — 대사로 읽지 않음

- 현재 저장소의 agent27/02_decide.py는 if 조건으로 행동을 선택하는 규칙 기반 예제다. 이 파일을 실행하면서 ‘LLM이 선택했다’고 설명하지 않는다.
- 본 대본의 판단 장면을 찍으려면 실제 LLM 호출과 JSON 결과 반환을 구현한 ask_llm이 필요하다. 이 대본 작성만으로 실행 소스가 수정된 것은 아니다.
- 현재 상태는 함수 호출 후에도 그대로 남도록 구성한다. STEP 1에서 캘린더 함수를 호출하거나 날짜를 채우지 않는다.
- 선택 결과 선공개와 본 실행 화면은 같은 실제 실행에서 확보한다.
- API 키 등 인증정보가 화면에 나오지 않도록 편집한다.
- 전체 예상 분량은 말하기·입력 속도에 따라 약 4~5분. 긴 입력 대기는 편집한다.

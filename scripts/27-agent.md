# #27. AI Agent란 무엇인가?
## 인트로부터 Closing까지 촬영용 대본
기준일: 2026-10-05 · 목표: 작은 v0.1의 행동 선택부터 v0.2의 실행·상태 업데이트·다음 판단까지 확인한다.
범위: 인트로, STEP 1~7, Closing. 캘린더와 교통편 검색은 예시 데이터를 반환하는 함수로 실행한다.

## 인트로

**강사**

AI가 나 대신 일정을 잡고, 티켓을 예매하고, 쇼핑까지 해준다.
이런 AI 에이전트 소개, 한 번쯤 들어보셨죠?

그런데 이런 AI 에이전트, 우리도 직접 만들 수 있습니다.

**학생**

제가요? 어디서부터 만들어야 할지 감도 안 잡히는데요.

**강사**

그렇죠. 저 말만 들으면 뭔가 엄청난 걸 만들어야 할 것 같잖아요.

그래서 이번 시간부터는 아주 작게 시작해서,
하나씩 기능을 붙여보려고 합니다.

우리가 만들 건 **나만의 출장 비서**예요.

자, 이렇게 일을 시켜보겠습니다.

**“다음 주 부산 출장 준비해줘.”**

이 말을 들은 우리 비서,
**가장 먼저 뭘 해야 할까요?**

[화면]
강사 중심. 요청 문구만 크게 표시한다.
일정·티켓·쇼핑 일러스트는 별도로 늘리지 않는다.

## STEP 1. 출장 준비를 맡기면 무엇부터 할까?

### 장면 1. 선택 결과를 짧게 먼저 보여주기

**강사**

교통편부터 찾을까요? 아니면 숙소부터?

우선 실행 결과를 잠깐 보겠습니다.

[화면 — 실제 LLM 호출에서 확보한 선택 결과]
```text
Selected Action | 선택한 행동
check_calendar    캘린더 확인
```

**강사**

캘린더를 먼저 확인하겠다고 하네요.
왜 이걸 골랐는지, 직접 만들어보면서 확인하겠습니다.

[촬영]
결과는 3~5초만 보여준다. 선택 이유는 장면 6에서 함께 확인한다.
촬영 전 실제 LLM 호출 결과를 확보한다. 이 화면은 그 실행 결과의 선공개다.

### 장면 2. 목표와 현재 상태 작성

**강사**

필요한 개발환경과 예제 코드는 영상 설명란에 정리해두겠습니다.

자, 먼저 우리가 맡길 일을 적겠습니다.
‘다음 주 부산 출장 준비’죠.

[화면 — 편집기에 입력]
```python
goal = "다음 주 부산 출장 준비"
```

**강사**

그런데 다음 주라고만 했지, 정확히 며칠인지는 아직 모르잖아요.
현재 알고 있는 정보에는 출장 날짜를 비워두겠습니다.

[화면 — 아래에 이어서 입력]
```python
current_state = {
    "trip_date": None  # 출장 날짜: 아직 모름
}
```

**강사**

여기서 None은 날짜가 아직 없다는 뜻이에요.

[촬영]
환경 설치 설명은 진행하지 않는다. 안내 자막만 잠깐 표시한다.
입력할 때 목표와 날짜 부분만 차례로 강조한다.

### 장면 3. 사용할 수 있는 기능 알려주기

**강사**

이제 AI에게 사용할 수 있는 기능을 알려줍니다.
캘린더 확인, 교통편 검색, 숙소 검색.
오늘은 이 세 가지 중에서 다음에 할 일을 골라보게 하겠습니다.

[화면 — 기능 목록 입력]
```python
available_actions = [
    "check_calendar",    # 캘린더 확인
    "search_transport",  # 교통편 검색
    "search_hotel"       # 숙소 검색
]
```

**강사**

지금은 기능의 이름을 알려주는 단계예요.
이름을 적었다고 캘린더가 바로 열리는 건 아니고요.

[촬영]
세 이름과 한글 주석을 함께 보여준다.
이 장면에서 각 함수 내부나 외부 서비스 연결을 설명하지 않는다.

### 장면 4. 작성한 내용을 Context로 연결

**강사**

지금 적은 걸 한글로 보면 이렇습니다.

[화면 — 코드 옆에 간단한 요약]
```text
목표              다음 주 부산 출장 준비
현재 알고 있는 정보  정확한 출장 날짜는 아직 모름
선택할 수 있는 행동  캘린더 확인 / 교통편 검색 / 숙소 검색
```

**강사**

앞에서 배운 Context죠.
LLM이 판단할 때 참고하도록,
목표와 현재 알고 있는 정보, 사용할 수 있는 기능을 함께 전달하는 겁니다.

[촬영]
새 도식으로 화면을 전환하지 않는다. 기존 코드 옆에 요약만 표시한다.
‘상황판’이라고 표현하더라도 사람이 작성해 전달한 정보임을 유지한다.

### 장면 5. LLM에게 다음 행동 선택 요청

**강사**

이제 LLM에게 이렇게 요청하겠습니다.

**“현재 상황에서 다음에 할 일을 하나 골라주고, 그 이유도 알려줘.”**

‘캘린더부터 확인해’라고 순서를 정해주지는 않겠습니다.
어떤 행동을 먼저 고를지 보죠.

[화면 — 실제 LLM 호출을 감싼 함수 사용]
```python
decision = ask_llm(
    goal,
    current_state,
    available_actions
)

print("Selected Action:", decision["action"])
print("Reason:", decision["reason"])
```

[촬영]
ask_llm은 실제 모델 호출이 구현된 함수여야 한다.
‘실제 LLM 호출’이라고 한 줄 표시한다.
함수 내부의 API 설정·인증·응답 파싱 설명은 이 장면에서 생략한다.
영상의 읽기 편의를 위한 표현 코드이며 현재 GitHub 예제와 동일한 실행 파일은 아니다.

### 장면 6. 결과에서 판단 확인

[화면 — 터미널 실제 실행 결과]
```text
Selected Action | 선택한 행동

Reason | 선택 이유
교통편과 숙소를 확인하려면
먼저 정확한 출장 날짜가 필요함
```

**강사**

캘린더 확인을 골랐네요.
이유도 보겠습니다.
교통편과 숙소를 찾으려면 정확한 날짜가 먼저 필요하다는 거죠.

우리가 작성한 건 목표, 현재 정보, 사용할 기능 목록이었죠.
그걸 보고 **지금 무엇을 먼저 할지는 LLM이 선택한 겁니다.**

[촬영]
실제 출력된 action과 reason을 사용한다.
이유의 문장이 달라지면 화면·대사를 그 결과에 맞춘다.
다른 행동이 나오면 그대로 확인하고, 입력 정보와 선택 이유를 검토한다.
정답처럼 보이도록 고정 문자열을 출력하지 않는다.

‘확인하겠다’는 말은 나왔는데, 아직 확인은 안 한 거죠.

## STEP 2. 그런데 선택했다고 실행된 건 아닙니다

**[화면 — STEP 1에서 실행한 선택 결과를 그대로 보여준다.]**

```text
Selected Action | 선택한 행동
check_calendar

Reason | 선택 이유
교통편과 숙소를 확인하려면
먼저 정확한 출장 날짜가 필요함
```

**강사**

자, `check_calendar`.
캘린더부터 확인하겠다고 골랐네요.

그럼 이제 출장 날짜를 알 수 있을까요?

**학생**

그런데 날짜는 안 나왔는데요?
캘린더를 확인한 거예요?

**강사**

아직 확인한 건 아닙니다.
지금은 **“캘린더를 먼저 확인해야겠다”라고 선택한 데까지**예요.

**[화면 — 코드 편집기로 전환. 선택 결과를 출력하는 부분을 가리킨다.]**

**강사**

코드를 보면,
LLM이 고른 행동을 화면에 출력하고 끝나죠.

`check_calendar`라는 이름은 나왔지만,
그 이름에 해당하는 기능을 실행하는 코드는 아직 없습니다.

여기까지 만든 걸 **v0.1**이라고 해보겠습니다.

그러면 이제,
선택한 행동이 실제로 실행되도록 연결해보죠.

## STEP 3. 선택한 행동을 진짜 실행해보자

**강사**

먼저 캘린더를 확인하는 함수 하나를 만들어보죠.

오늘은 실제 캘린더에 연결하는 대신,
**캘린더를 조회했을 때 이런 결과가 돌아온다고 가정하겠습니다.**

**[화면 — 코드 편집기에서 아래 함수를 작성한다.]**

```python
def check_calendar():
    return {
        "trip_date": "2026-10-08",
        "meeting_time": "14:00"
    }
```

**강사**

출장 날짜는 10월 8일,
미팅 시간은 오후 2시.

이 함수를 실행하면
이 두 가지 정보를 돌려주도록 만든 겁니다.

이제 LLM이 고른 행동이 `check_calendar`라면,
방금 만든 함수를 실행하도록 연결하겠습니다.

**[화면 — 앞에서 받은 선택 결과 아래에 실행 코드를 추가한다.]**

```python
selected_action = decision["action"]

if selected_action == "check_calendar":
    result = check_calendar()
    print(result)
```

**강사**

여기서 `check_calendar()`가
실제로 함수를 실행하는 부분입니다.

LLM이 고른 이름을 보고,
프로그램이 해당 기능을 실행하는 거죠.

자, 다시 실행해볼까요?

**[화면 — 터미널에서 실행한다. 선택 결과 아래에 함수의 반환값이 출력된다.]**

```text
Selected Action | 선택한 행동
check_calendar

{'trip_date': '2026-10-08', 'meeting_time': '14:00'}
```

**강사**

이번에는 날짜와 시간까지 나왔네요.

아까는 `check_calendar`라고 고르고 끝났는데,
이번에는 선택한 함수가 실행되고
그 결과까지 돌아왔습니다.

**이렇게 LLM의 판단을 실제 기능의 실행으로 이어준 겁니다.**

지금은 예시 데이터를 돌려주는 함수지만,
나중에 이 함수 안에 실제 캘린더를 조회하는 코드를 넣으면
조회한 일정이 돌아오겠죠.

여기까지 실행 기능을 붙인 걸
**v0.2**라고 해보겠습니다.

## STEP 4. 실행 결과로 현재 상태를 바꿔보자

**강사**

그런데 결과가 나왔다고
LLM이 이 날짜를 바로 알고 있는 건 아닙니다.

지금 결과는 프로그램이 받아서
화면에 출력한 상태예요.

출장 날짜를 알았으니 다음 일을 고르게 하려면,
**이 결과를 현재 상태에 반영해서 LLM에게 다시 전달해야겠죠.**

**[화면 — 캘린더 함수 실행 결과를 받은 다음 줄에 코드를 추가한다.]**

```python
state["current_state"].update(result)
```

**강사**

캘린더에서 돌아온 날짜와 시간을
현재 상태에 넣겠습니다.

아까는 출장 날짜가 비어 있었죠.
이제는 이렇게 바뀝니다.

**[화면 — 변경된 현재 상태를 보여준다.]**

```python
"current_state": {
    "trip_date": "2026-10-08",
    "meeting_time": "14:00"
}
```

**강사**

다음 판단에는
“출장 날짜를 모른다”가 아니라
**“10월 8일 오후 2시에 미팅이 있다”는 상황을 전달하는 겁니다.**

그럼 바뀐 상태를 넣어서
LLM에게 다시 물어보겠습니다.

목표는 그대로 부산 출장 준비인데,
이제 날짜와 미팅 시간을 알고 있죠.

다음에는 뭘 고를까요?

**[화면 — 앞에서 사용한 LLM 요청에 업데이트된 현재 상태를 전달한다. 실행 전 잠깐 멈춰 시청자가 예상할 시간을 준다.]**

```text
Goal | 목표
다음 주 부산 출장 준비

Current State | 현재 상태
출장 날짜: 2026-10-08
미팅 시간: 14:00

Available Actions | 가능한 행동
- check_calendar    캘린더 확인
- search_transport  교통편 검색
- search_hotel      숙소 검색
```

**[화면 — LLM 응답을 보여준다. 아래는 교통편을 선택한 응답 예시이며, 촬영에서는 실제 출력에 맞춰 설명한다.]**

```text
Selected Action | 선택한 행동
search_transport

Reason | 선택 이유
10월 8일 오후 2시 미팅에 맞춰
부산에 도착할 교통편을 확인해야 함
```

**강사**

이번에는 교통편 검색을 골랐네요.

처음에는 날짜를 몰라서 캘린더 확인을 골랐고,
날짜와 시간을 알려주니 교통편 검색을 고른 겁니다.

우리가 코드에
“캘린더 다음에는 교통편을 검색해”라고
순서를 정해둔 건 아니죠.

**실행 결과로 상황이 바뀌고,
LLM이 그 상황을 보고 다음 행동을 고른 겁니다.**

## STEP 5. 그러면 결국 사람이 다 만들어주는 것 아닌가요?

**학생**

그런데 캘린더 확인도 우리가 만들었고,
교통편 검색도 우리가 연결해줘야 하잖아요.

그러면 결국 사람이 다 만들어주는 거 아닌가요?

**강사**

맞습니다.
캘린더를 확인하거나 교통편을 검색하는 기능은
개발자가 사용할 수 있게 만들어줘야 합니다.

그리고 LLM이 그 기능을 고를 수 있도록
**각 기능이 어떤 일을 하는지 설명도 함께 전달합니다.**

**[화면 — Tool 이름과 설명]**

```text
check_calendar
출장 날짜와 미팅 시간을 확인한다.

search_transport
출장 날짜와 미팅 시간에 맞는 교통편을 검색한다.

search_hotel
출장 일정에 맞는 숙소를 검색한다.
```

**강사**

앞에서 배운 **Tool의 설명**이 여기서 쓰이는 거죠.

LLM은 현재 상황과 이 설명을 보고
어떤 기능을 사용할지 고릅니다.

그러면 프로그램이
**LLM이 선택한 기능을 실제로 실행하는 겁니다.**

---

## STEP 6. 실행했는데, 차표가 없다면?

**강사**

그럼 선택한 교통편 검색도 실행해보죠.

이번에도 실제 예매 사이트에 연결하는 대신,
검색 결과를 돌려주는 예시 함수를 만들겠습니다.

그런데 이번에는
원하는 차표가 없다고 해볼게요.

**[화면 — 코드 편집기에 교통편 검색 함수를 작성한다.]**

```python
def search_transport(trip_date, meeting_time):
    return {
        "status": "no_tickets",
        "message": "미팅 시간 전에 도착하는 KTX 차표가 없습니다."
    }
```

**강사**

이런 결과가 돌아오면,
다음에는 뭘 해야 할까요?

우선 실행해서 확인해보죠.

**[화면 — 다시 판단에서 받은 행동 이름을 사용해 교통편 검색을 실행한다.]**

```python
selected_action = decision["action"]

if selected_action == "search_transport":
    result = search_transport(
        state["current_state"]["trip_date"],
        state["current_state"]["meeting_time"]
    )
    print(result)
```

**강사**

캘린더에서 확인한 날짜와 시간을
교통편 검색 함수에 전달해서 실행하겠습니다.

**[화면 — 터미널 실행 결과]**

```text
{'status': 'no_tickets',
 'message': '미팅 시간 전에 도착하는 KTX 차표가 없습니다.'}
```

**강사**

아, 차표가 없다고 나왔네요.

검색은 실행됐지만,
**출장에 필요한 교통편을 구한 건 아닙니다.**

이 결과까지 알려줘야
LLM도 다음 방법을 판단할 수 있겠죠.

**[화면 — 교통편 검색 결과를 현재 상태에 추가한다.]**

```python
state["current_state"]["transport_result"] = result
```

**강사**

이번에는 현재 상태에
“교통편을 검색했지만, 조건에 맞는 KTX 차표가 없다”는 결과를 넣겠습니다.

이 상태를 LLM에게 다시 전달하면,
다른 이동 방법을 찾아볼지,
사용자에게 일정을 조정할 수 있는지 물어볼지 판단하게 할 수 있겠죠.

다만 그러려면 다른 교통편을 검색하거나
사용자에게 질문할 수 있는 행동도 제공해야 합니다.

**다음 행동을 판단하는 것과,
그 행동을 실행할 수 있는 기능이 있는 것.
둘 다 필요하다는 거예요.**

---

## STEP 7. 실행 결과를 보고 다시 판단하는 AI

**강사**

자, 지금까지 만든 걸 보면요.

처음에는 LLM이 행동을 고르고 끝났죠.
거기에 실행 코드를 붙였더니 결과가 돌아왔고,
그 결과를 현재 상태에 넣어 다시 판단하게 했습니다.

그런데 실행했다고 항상 일이 해결되는 건 아니네요.
방금처럼 차표가 없을 수도 있으니까요.

**그래서 Agent는 실행 결과를 보고,
목표를 이루려면 다음에 무엇을 해야 할지 다시 판단해야 합니다.**

지금은 우리가 코드를 하나씩 실행하면서
이 과정을 확인했는데요.

이 과정을 프로그램이 반복하도록 연결하면
매번 우리가 다음 실행을 눌러줄 필요가 줄어들겠죠.

## 촬영 전 확인 — 대사로 읽지 않음

- 현재 저장소의 agent27/02_decide.py는 if 조건으로 행동을 선택하는 규칙 기반 예제다. 이 파일을 실행하면서 ‘LLM이 선택했다’고 설명하지 않는다.
- 본 대본의 판단 장면을 찍으려면 실제 LLM 호출과 JSON 결과 반환을 구현한 ask_llm이 필요하다. 이 대본 작성만으로 실행 소스가 수정된 것은 아니다.
- 현재 상태는 함수 호출 후에도 그대로 남도록 구성한다. STEP 1에서 캘린더 함수를 호출하거나 날짜를 채우지 않는다.
- 선택 결과 선공개와 본 실행 화면은 같은 실제 실행에서 확보한다.
- API 키 등 인증정보가 화면에 나오지 않도록 편집한다.
- 인트로·STEP 1의 예상 분량은 말하기·입력 속도에 따라 약 4~5분. 전체 분량은 추가 장면을 포함해 리허설에서 확인한다. 긴 입력 대기는 편집한다.
- 작성 기준: [대본 작성 기준](../docs/script-guidelines.md)
- 장면별 촬영·논리·의도: [개선 스토리보드](../storyboards/27-intro-step1-v2.md)

- STEP 2는 STEP 1 장면 7~8과 내용이 겹친다. 촬영 편집 시 기존 상태 확인 장면 뒤에 바로 코드 설명으로 이어가며 반복 질문은 한 번만 사용한다.
- STEP 3부터 selected_action은 실제 LLM 응답의 decision["action"]을 사용한다.
- STEP 4의 state는 STEP 1 변수를 묶은 표현이다. 촬영 소스에서 state = {"goal": goal, "current_state": current_state, "available_actions": available_actions}를 먼저 구성한다.
- STEP 4의 재판단은 decision = ask_llm(state["goal"], state["current_state"], state["available_actions"])로 새 응답을 받는 과정이다. 설명용 화면만 바꾸고 이전 decision을 재사용하지 않는다.
- STEP 5의 Tool 설명은 실제 LLM 입력에도 포함해야 한다. 화면에 설명을 보여주는 것만으로 모델에 전달되는 것은 아니다. 함수 이름만 있는 기존 예제와 구분하며, 설명을 추가한 뒤 호출한 실제 결과를 사용한다.
- 교통편 예시 함수는 입력 조건을 실제 검색에 사용하지 않고 고정 결과를 반환하는 모의 함수다. 차표 없음 이후 대안 판단·실행은 가능성 설명이며 이번 촬영에서 구현·실행 완료로 표현하지 않는다.
- 이 업데이트는 대본 파일에 한정하며 실행 소스는 변경하지 않는다.

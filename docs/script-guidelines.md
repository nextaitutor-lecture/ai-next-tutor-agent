# AI옆자리과외 대본 작성 기준

기준일: 2026-10-03

## 인트로 기본 패턴

익숙한 상황 → 나도 할 수 있다는 기대 → 학생의 현실적인 막막함 → 작게 시작한다는 안심 → 구체적인 요청·문제 → 시청자의 판단을 유도하는 질문

- 기술 용어보다 시청자가 아는 상황으로 시작한다.
- 남의 기술을 소개하는 데서 시청자가 직접 해볼 가능성으로 연결한다.
- 학생은 내용을 미리 아는 질문 대신 실제 의문·부담·오해를 표현한다.
- 강사는 부담을 인정하고 아주 작게 시작해 기능을 붙여간다고 안내한다.
- 강의 안내를 길게 하지 않고 실제 사례로 들어간다.
- 설명 전에 시청자가 예상할 수 있는 구체적인 단서를 제공한다.
- 마지막 질문은 본편의 첫 실행 결과와 연결한다. 시청자가 자신의 예상과 실제 결과를 비교하고 싶도록 만든다.
- 매번 같은 문장을 반복하지 않고 회차 주제에 맞게 변형한다.
- 모든 단계를 별도 장면으로 나누지 않는다. 한두 문장에 여러 역할을 담을 수 있다.
- 학생은 실제로 걸릴 만한 지점에서만 등장한다.

## 대본 논리·의도 구조표

기존 열: STEP / 화면·상황 전개 / 시청자가 자연스럽게 할 생각 / 학생의 역할 / 강사의 핵심 전개 / 논리적 의도

인트로도 본편의 첫 문제로 이어지는 과정으로 설계한다.

| 인트로 흐름 | 화면·상황 전개 | 시청자가 자연스럽게 할 생각 | 학생의 역할 | 강사의 핵심 전개 | 논리적 의도 |
|---|---|---|---|---|---|
| 익숙한 상황 | 익숙한 AI 활용 장면 | 이런 얘기 들어봤어 | 필요하면 공감, 억지 질문 생략 | 익숙한 상황으로 시작 | 기술 설명 없이 관심 형성 |
| 내 가능성으로 연결 | 우리도 직접 만들 수 있다는 제안 | 나도 만들 수 있다고? | 놀람 표현 | 직접 해볼 일 제시 | 구경에서 참여로 전환 |
| 현실적인 막막함 | 어디서 시작할지 모르는 상황 | 나는 어떻게 만들지? | 부담·의문 대변 | 부담 인정, 작게 시작한다고 안내 | 시작할 수 있다는 안심 |
| 구체적인 첫 문제 | 실제 요청 제시 | 무엇부터 해야 하지? | 필요하면 예상 제시 | 설명보다 먼저 요청 제시 | 판단할 단서 제공 |
| 본편으로 연결 | 첫 행동 질문 → 실행 결과 | 내 생각대로 움직일까? | 결과에 자연스럽게 반응 | 실제 결과를 확인하며 본편 시작 | 예상과 결과의 비교로 시청 지속 |

### 작성 순서와 점검

1. 본편에서 처음 확인할 결과를 정한다.
2. 그 결과를 궁금하게 만드는 마지막 질문을 정한다.
3. 시청자가 예상할 수 있도록 앞의 상황과 대화를 배치한다.

- 기대: 이번 영상을 보면 내가 무엇을 해볼 수 있는가?
- 판단: 시청자가 스스로 예상할 구체적인 문제가 있는가?
- 연결: 마지막 질문의 결과를 본편에서 바로 확인하는가?

## 본편의 기본 방향

구체 상황·현상 → 시청자 판단 → 의문·반론 → 문제·차이 발견 → 개념·원리 → 실제 동작 적용 → 결과·가치 → 전체 구조 정리

- 내부 논리는 치밀하게, 실제 말하기는 자연스럽게 작성한다.
- 학생을 목차를 넘기는 진행자로 사용하지 않는다.
- 강사는 질문마다 즉시 정답을 설명하기보다 사례·실행 결과를 함께 보며 결론을 발견하도록 한다.
- 억지 농담보다 시청자의 속마음을 대신하는 가벼운 너스레를 사용한다.
- 실전 개발은 작은 v0.1부터 시작해 문제를 발견할 때마다 기능을 붙이는 누적 개발 서사로 전개한다.
- Agent 시리즈의 공통 예시는 출장 준비 Agent, 대표 요청은 “다음 주 부산 출장 준비해줘.”로 유지한다.
